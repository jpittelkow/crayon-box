# Gotchas

Non-obvious traps, workarounds and lessons learned. Add one bullet per gotcha with the date found and, if it
came from a session, the journal entry.

_Last updated: 2026-11-21_

- ADRs are never rewritten once Accepted; a change gets a new ADR that supersedes the old one (ADR 0001).
  Proposed ADRs may still be edited before acceptance.
- Dev machine is Windows; shell commands in docs should work in PowerShell or Git Bash.
- Tauri has no official plugin for Windows Credential Manager or printing (checked 2026-11-14; ADR 0002).
- OpenRouter per-key spending limits could not be confirmed from its own docs on 2026-11-14; ADR 0006 is worded
  to work either way.
- A keyboard hook can't block Win+L or Ctrl+Alt+Del (checked 2026-11-14; ADR 0014).
- The mockup canvas and the design system are artifacts, not files in this repo (links in the ADR index). Their
  files were generated by a throwaway script, so later changes are made by editing the artifact's own files.
  Kid-screen artboards hold every style inline; a change to a shared value (a color, a button size) has to be
  made in each artboard and in the design system's `tokens.json` (found 2026-11-14).
- Publishing artifact files from the session scratch folder on the dev machine only worked with absolute source
  paths; relative ones were refused by a read-permission rule (found 2026-11-14). The `root` must also use the
  long user folder name (`C:\Users\<user>\...`), not the short `ABCDEF~1`-style one the session reports: with
  the short name every file was refused the same way (found 2026-11-14). Reading only one file of a canvas
  (`read` with `path`) is not enough before a publish: it is refused until the artifact itself is read (`read`
  with just the `url`) in the session (found 2026-11-14).
- Tooling resolved on 2026-11-14: Vite 8, Vitest 5, TypeScript 7, Playwright 1.65, Node 24. TypeScript 7 is
  strict about `Uint8ClampedArray<ArrayBuffer>` vs `ArrayBufferLike` when building `ImageData`.
- In page SVGs, white fills count as paper (only dark pixels become lines), so a white fill can hide lines
  behind a shape. The fish page uses this for its fins (found 2026-11-14).
- The bucket must read the color when the finger touches, not after the worker answers; a fast color pick in
  between used to fill with the new color. A browser test now covers it (fixed 2026-11-14).
- Two Playwright `tap()` calls started together can reach the page in either order. To test "this happened
  before the worker answered", dispatch the pointer events in one `page.evaluate` (found 2026-11-14).
- Canvas compositing can be off by one or two per color channel, so browser tests compare pixels with a
  tolerance of 3 (found 2026-11-14).
- A parent-world button styled `display: inline-flex` ignores the `hidden` attribute unless CSS restores it;
  `parent.css` has a `[hidden]` rule for that (found 2026-11-14).
- The keyboard is blocked app-wide (ADR 0003) except while `body[data-world="parent"]`, so the name field can be
  typed in. Browser shortcuts (Ctrl/Alt) stay blocked there too (2026-11-14).
- Scripts outside the repo can't import `@playwright/test` by name; import it by file URL from the repo's
  `node_modules` (found 2026-11-14).
- Edge kiosk mode (`--kiosk`, both kiosk types) always runs InPrivate, so IndexedDB is gone when the window closes.
  Playtests use an Edge app window instead (`--app`, own `--user-data-dir`; ADR 0020). Checked in Microsoft's
  kiosk-mode docs on 2026-11-14.
- Container query units (`cqh`, `cqw`) measure the container inside its padding: don't subtract the padding again
  (found 2026-11-14, page library tiles).
- The page check treats a strip of paper narrower than 6 px between a line and the page edge as a gap and fills
  it. Real pages should keep about 40 px of margin; test fixtures need margins wider than the gap limit
  (found 2026-11-14).
- Running a `.cmd` from the Bash tool with `cmd //c` executes it for real; `scripts/playtest.cmd` opened an Edge
  window that way once. Check scripts' parts separately (2026-11-14).
- A helper script saved as `$TEMP/types.py` shadowed Python's own `types` module for every later script run from
  `$TEMP`. Run throwaway scripts with `python -I`, and don't name them after standard modules (2026-11-14).
- Several Claude sessions can work in this folder at once (a racing-game session wrote ADR 0021 while this one
  was writing ADRs). Check `ls docs/adr` right before numbering a new ADR (and `origin/main` and other branches after a
  `git fetch`: 0038 was taken on `main` and again on a branch on 2026-11-15), and commit only your own files
  (found 2026-11-14).
- Page art traps the check caught: a wheel top within ~6 px of the body line, a flagpole running beside a seat,
  and a smile ending a few px short of an outline. Lines should either cross clearly or keep 20 px apart
  (2026-11-14).
- The Browser pane pauses a page's animation frames while it is hidden, so a canvas game looks frozen to the
  tools and timings read as zero. The engine test exposes `bakeoff.tick()` to run frames by hand
  (found 2026-11-14).
- Babylon.js compiles shaders in the background and draws nothing for the first frames; time it only once its
  draw-call count is above zero. Other Babylon and three.js matching traps are in
  `spikes/engine-bakeoff/README.md` (found 2026-11-14).
- **Rules for anything that saves data, so sync keeps working (ADR 0024):** save through the storage interface
  only; one file per thing that can change on its own (kids are `kids/<id>/profile.json`, not one list), because
  the newest change wins per file; device-only data goes under `local/`; new ids come from `randomId`; built-in
  defaults are written with `asDefault` so a family's real data replaces them on first sync.
- Deleted items leave a record forever (so deletions reach other devices). Nothing prunes them yet; revisit when
  the sync server exists.
- If every kid were deleted across two devices, a device would re-create the three starting profiles, and the
  remembered deletions would remove them again on the next sync. Not handled; the parent area already refuses to
  delete the last kid on one device (2026-11-14).
- Playwright's `reuseExistingServer` reuses whatever answers on its port. Another session's dev server on 5180
  made all 27 browser tests fail by serving a different page. The tests now use port 5391 (found 2026-11-14).
- Chrome's DevTools protocol lifts one finger by leaving it out of a `touchMove`; a `touchEnd` must carry no touch
  points and lifts every finger (found 2026-11-14, two-finger undo test).
- In the clean-up step, pick the ink/paper threshold from the picture before adding the white margin; the margin
  pulls the automatic threshold toward the paper and turns gray paper into ink (found 2026-11-14).
- Settings that change independently get their own file (`sounds.json`, `gate.json`), because sync settles
  conflicts per file (ADR 0024).
- This dev machine often runs at about 70% CPU before tests start. The full browser suite can then time out in a
  random test; `npx playwright test --workers=4` is steady. CI is the reference (2026-11-14).
- The Windows app has a Content Security Policy (`src-tauri/tauri.conf.json`), the browser version has none. Anything
  new that loads from elsewhere (OpenRouter in phase G, a sync server in phase C) must be added to it or it works
  in the browser and fails only in the installed app. The built app was checked under that policy with a one-off
  script on 2026-11-14 (fill worked, nothing blocked).
- Rust 1.94 (MSVC) is on the dev machine now, used only for `cargo check` and `cargo test` in `src-tauri/`
  (builds and installers still come from CI). Point `CARGO_TARGET_DIR` at one shared folder outside the repo so
  worktrees reuse it; a first check takes about 1.5 minutes. `cargo check` also updates `Cargo.lock`, which can be
  committed; before, CI's `cargo-lock` artifact was the only source (2026-11-14).
- Device-only settings (the kiosk lock, sync's own settings) go under `local/` in a namespace: ADR 0024's rule,
  which the storage layer already keeps out of sync (`types.ts`). Don't invent another prefix (2026-11-14).
- Several sessions share this folder and its git index. A plain `git commit` takes whatever anyone has staged:
  one fix commit (941ad5d, local only) swept in another session's staged deletion. Commit your own files with
  `git commit -- <paths>`, which ignores other staged changes (2026-11-14).
- A release tag must match `package.json`'s version (`v0.1.0` for `0.1.0`); `release.yml` stops otherwise. Bump
  the version on main first, then tag (2026-11-14).
- A PR can be merged while later commits are still being pushed to its branch; they then never reach main.
  After a merge, check `git log origin/main` holds the branch's last commit (PR #1, 2026-11-14).
- Don't stage anything (not even `git rm`) until you are about to commit: another session's commit in this
  folder takes whatever is staged. A staged deletion of `src/games/racing/sim/scene.ts` went out in someone
  else's commit and left `main` unable to build until the matching change landed (found 2026-11-14).
- Storage keys become Windows file names in the installed app (`storage/files.ts`). Windows ignores case, so
  capitals and anything outside `a-z0-9._-` are `%`-escaped; keep keys lower case to keep the files readable
  (2026-11-14).
- A new folder the Windows app writes to must be added to `fs:scope` in `src-tauri/capabilities/default.json`, or
  the fs plugin refuses it only in the installed app (2026-11-14).
- The repo on GitHub is `jpittelkow/crayon-box`; the local folder is still called `kidsapp`. The updater's
  endpoint in `tauri.conf.json` uses the GitHub name (2026-11-14).
- `bundle.createUpdaterArtifacts` makes `tauri build` fail without `TAURI_SIGNING_PRIVATE_KEY`, so it is only
  turned on in `release.yml` (`--config`), never in `tauri.conf.json`; ordinary CI builds have no key
  (2026-11-14).
- Node 24 runs `.ts` files directly (type stripping), which is how `release.yml` runs
  `src/tools/releaseManifest.ts`; keep that file to erasable TypeScript (no enums, no parameter properties)
  (2026-11-14).
- The Windows app's CSP `connect-src` includes `http: https:` so it can reach the family sync server on the
  home network (any address). The sync server sends CORS headers for the same reason (2026-11-14).
- Tests can import the sync server (`server/src/*.ts`) directly: vitest and Playwright both run it in-process,
  which is how the client is tested against the real thing. The root tsconfig allows `.ts` import paths for
  this (2026-11-14).
- The browser tests draw WebGL in software; the driving game's toy look takes seconds to start there, so
  `driving.spec.ts` runs its tests one at a time with longer timeouts (2026-11-14).
- **No Prettier config** (2026-11-14): `npx prettier --write` uses 80 columns and reflows whole files. The code is
  written to 120 columns with single quotes; format by hand or with `--print-width 120 --single-quote`, and check
  the diff for unrelated reflow.
- Preview servers are capped at 5 per folder across all chats; when full, take screenshots with a script that
  starts Vite itself (`spikes/*/shoot.mjs`) (2026-11-15).
- TRELLIS.2 Space: decimation target can't go below 50,000 triangles; cut down afterwards (meshoptimizer's
  simplifier ships in `three/addons/libs`). Its GLBs face +x; turn them +90° about y to face +z (2026-11-15).
- The driving simulation looks things up through a grid (`sim/grid.ts`, 2026-11-16) and toys far from any moving
  vehicle sleep. `grid.test.ts` compares every grid answer with the slow way step by step, so a change to roads,
  zones, water or toys that the grid doesn't index shows up there first. Most of the old cost was rebuilding each
  toy's body points, not the search.
- ADR 0035 says every reachable place is within 25 m of a road. Neither map keeps that (farthest 46 m, about a
  quarter of the land over 25 m) and no test checks it (measured 2026-11-15). Don't quote 25 m as a tested rule.
- **Parallel worktrees (2026-11-16):** give each one its own browser-test port with `PW_PORT` (the gallery and
  picture scripts take `GALLERY_PORT` and `PICTURES_PORT`), stop dev servers when done (a leftover one held 5393
  all night), and give scratch files names of their own: lanes sharing one scratch folder used each other's
  `pr-body.md` twice. `gh pr merge --delete-branch` fails locally when another worktree has `main` checked out; the
  merge still happens, then delete the branch with `git push origin --delete <branch>`.
- **CI draws the game in software:** a frame can take seconds and the game runs at most 5 steps a frame, so
  browser waits on driving game state need about 60 s; the detail watcher ignores frames over 500 ms, so the
  picture never turns down there (2026-11-16, the driving tests that flaked on `main`).
- To test timer rules in the browser quickly, `page.clock.install()` plus `fastForward` works; on the letters
  trace screen, synthetic pointer events sent in one `page.evaluate` finish a letter at once (2026-11-16).
- A driving set piece that slows cars must cap the top speed, not only brake, or the car stays fast for half a
  second (2026-11-16, mud and ford).
- PowerShell's `Get-Content`/`Set-Content` mangle UTF-8 in this repo's files; edit with Node or the file tools
  (2026-11-16).
- Playwright's `tap()` never fires on a button that keeps moving (Kitchen's next arrow pulses): it waits for the
  element to be "stable" until the test times out. Tap its middle with `page.touchscreen.tap` instead, as
  `kitchen.spec.ts` does (2026-11-21).
- A game's timed logic should not hang off `requestAnimationFrame` alone: frames stop in a hidden pane. Kitchen's
  oven runs on a timer and only the drawing on frames (2026-11-21).
- To see a mockup artboard before publishing it: save a copy without the `support.js` line and with its `{{holes}}`
  filled in, and screenshot that with the repo's Playwright (imported by file URL). The Browser pane shows a local
  file outside the project only as a snapshot its tools can't read. Stay clear of `clipPath`, `mask` and `<use>` in
  artboards: none of the canvas's boards use them, so they are untried there (2026-11-21).
