## Session: ADR review and revisions
**Done**
- Reviewed ADRs 0001–0014 and, with the owner's go-ahead, applied every recommendation to the Proposed ADRs.
- Added ADR 0015 (testing approach). Updated the ADR index, project state, open questions and gotchas.

**Decided** (all still Proposed)
- 0002: credential storage uses the `keyring` crate; printing uses the webview's print dialog.
- 0003, 0004: every finger paints its own stroke; undo capped at 20 steps or about 150 MB.
- 0005: page ids are prefixed `builtin:` / `family:`; `ageMin` replaced by `detail`; small regions are a
  warning, not a failure; loose files are converted at launch.
- 0006: AI page maker moves to the installer milestone; spending limit and provider-training guidance added.
- 0007: working copy in the app data folder, finished picture exported to Pictures; one previous version kept
  per picture.
- 0008: parent gate is a 1-second hold, then reading three number words; parent area locks itself after 3 minutes.
- 0009, 0013: draft releases published by hand; signing key backed up; private code repo + public releases repo.
- 0011: rules for AI-made built-in pages, sounds, icons, fonts and a code license.
- 0012: game registry entry split from the game module; unmount waits for saving.
- 0014: three named milestones, web milestone scope, a laptop setup list, Win+L and antivirus caveats.

**Learned**
- Checked by web search: no official Tauri keyring or print plugin; Edge kiosk command line; the Windows 11
  three- and four-finger touch gesture setting; Win+L can't be blocked by a keyboard hook; OpenRouter's
  no-training account setting. Not confirmed: OpenRouter per-key spending limits, and `tauri-action` behavior
  when drafting a release in another repo.
- The mockups predate these changes and were not compared against the revised ADRs.
