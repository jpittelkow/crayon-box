**Learned**

  turning and resizing parts, typing a name) is for older kids.

## Session: research, what a Linux version would take

**Asked:** what it would take to get the app on Linux. Research only; nothing built, no decision.

**Found**
- The web app and the family server already run on Linux (CI tests on Ubuntu; the server is a container).
- The shell is close: `kiosk.rs` already compiles its keyboard hook only on Windows, and the fs, opener, autostart
  and updater plugins all support Linux. Missing: a Linux bundle target (`bundle.targets` is `nsis` only), a Linux
  build job, a `linux-x86_64` entry in `latest.json` (`releaseManifest.ts` types only Windows), and a relaunch
  after an update (the NSIS installer restarts the app; an AppImage update does not).
- The real risk is the engine: Tauri on Linux draws with WebKitGTK, not Chromium. Untested there: the driving
  game's WebGL speed, the microphone recordings (WebKitGTK denies `getUserMedia` unless the shell answers the
  permission request), mp3 playback (needs GStreamer, bundled into an AppImage with `bundleMediaFramework`),
  touch and pen events, the speech fallback.
- The keyboard lock has no Linux twin on Wayland. The usual answer is a kids' account whose session is only the
  app (a kiosk compositor such as `cage`), which locks more than the Windows hook does.

**Next**
- If the owner wants it: say which Linux device, then a spike (the browser tests on Playwright's WebKit in CI, and
  a Linux build tried on that device) before an ADR.
